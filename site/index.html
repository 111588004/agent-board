先講清楚

它很小，而且刻意很小

  • 單人、本機。沒有帳號、沒有雲端，預設只聽 127.0.0.1。
  • 資料是你電腦上的 SQLite 檔，備份就是複製檔案。
  • 只有任務、子任務兩層。沒有 Epic、Sprint、權限。
  • MIT 授權，不合用就改。

怎麼接進來

人用網頁，agent 用 CLI 或 MCP，寫的是同一張卡

每個入口一行指令就接上。背後只有一個 REST API 在寫資料，所以幾個 agent 同時動也不會互相蓋掉。

人

網頁看板

拖卡、改優先度、寫描述。每 3 秒自動更新，agent 改了你馬上看到。名字對不上時看板替你挑了專案？卡上會標「待確認」，按一下就好。

任何 agent

CLI

會跑 shell 的 agent 都能用。狀態和優先度接受「進行中」「高」這類口語，專案可以用你叫它的名字。

10 個工具

stdio 模式，server 沒開會自己帶起來。看板不確定你的意思時回「NEEDS USER INPUT」，agent 用自己的提問工具問你，不替你選。

你可能想問

疑問

為什麼不直接用 Jira、Plane 或 GitHub Issues？

它們各有適合的場景，而且很可能你已經在用，不必換。Agent Board 的設計立場不同：本機、輕量、人與 agent 用同一組動詞，並且不假設每件事最後都是 code。如果你的進度很大一部分靠溝通解決，或你想讓多個 CLI agent 在你自己的機器上共用一份看板，值得試一分鐘。

資料存在哪？只能在本機嗎？

存在你機器上的 SQLite 檔案，每個 workspace 一個檔案。目前的設計就是單人、本機，不是多人協作或雲端服務。

安全嗎？

原始碼公開，MIT 授權，你可以自己讀。從 0.4.1 起，server 預設只綁 127.0.0.1，同一個網路上的其他裝置連不到它（0.4.0 與更早的版本會監聽所有網路介面，請升級）。它仍然沒有帳號系統：要用 HOST 設定把它開放到區網，等於讓同網路的人都能讀寫你的看板，請不要這樣做，也不要開放到公網。我們還沒有防範惡意網頁對 localhost 發請求這類瀏覽器端的攻擊。

怎麼跟 Claude Code、Codex 搭？

MCP：在客戶端設定裡加 npx -y @limao.li.design/agent-board mcp（Claude Code 可直接用上方「開始」裡的 claude mcp add 指令）。server 沒開時會自動帶起。也可以直接讓 agent 呼叫 CLI。Claude Code 另有 mod，見上方「怎麼接進來」。

多個 agent 同時改同一張卡會怎樣？

卡片上的欄位是最後寫入的贏，但每次狀態、負責人、優先度的變更都會留在卡片歷史，碰撞看得見，不假裝能防止。程式碼本身不會撞：每張卡有 worktree 和 branch 欄位，慣例是一個 agent 一個 git worktree，各改各的分支，卡上記著誰在哪條分支，交接時下一個 agent 直接接著那條分支做。
